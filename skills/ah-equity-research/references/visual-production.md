# 从版式设计到真实页面

## 先看真实参考，再确定本稿视觉语言

优先使用用户给定范本；没有范本时选择少量公开中文券商公司深度PDF，通常2–3份足以比较。优先券商或发行人官网，可用明确标注来源的公开转载。真正打开并查看首页、双图正文、估值和财务附录的完整页面，记录报告名称、日期、原始链接及实际看到的页码；搜索摘要、PDF文字提取和截图占位符不算视觉查看。

提炼版心、阅读顺序、信息密度、图表组合、字重、表格线与页眉页脚，形成简短本稿设计决定。不要复制Logo、署名、执业信息、水印、大段文字或整页图像；用户要求某机构“风格”时，可参考其结构，不宣称自选配色属于该机构官方规范。参考报告的日期仅用于设计溯源，不因此把其中分析或数字引入本稿研究。

## 四种版式

- 首页即研究摘要。公司名、具体研究命题、日期先行；左侧窄栏放市场快照或紧凑估值参数，右侧宽栏陈述有证据的核心判断、盈利预测和风险。默认原生Word分栏为5cm / 0.7cm栏距 / 11.6cm，不用巨大布局表承载正文。条件价值的性质放在数值旁，不让超大数字与小字限制产生误导。缺少核验行情时不编造股价曲线或评级。
- 正文按同一论点组织成组图表。17.3cm版心内双图每侧标题带宽8.325cm，中间用0.65cm真实空白列分隔；各半栏标题使用独立整行色带，相关两图水平对齐。完整图画布在所属色带内左右各留1.2mm，默认通栏17.06cm、半栏8.085cm，图内有效内容充分利用画布。不同计量单位用独立面板，不把数列挤到不可读的双轴上。标题下正文先解释问题，再看图，图后解释含义。
- 估值页把经营驱动、价值构成、现价隐含条件和情景组织在一起，完整计算细项可下沉附录。宽表/敏感性用通栏，避免一个参数一页或图后机械重复同值表。
- 附录按经营驱动、财务预测、估值细项和研究补充分组，组合关联表格与图。默认进入简化层级：章标题浅底深字配细底线，图表标题浅带深字，列头白底深字，重点财务行轻填充，普通行白底或极轻斑马纹；金额右对齐、叙述左对齐。减少装饰与多余段间距，不压缩数字字号；重要数据与分组保留。来源定位和单元格索引只存support。

## 色彩与字体层级

v1.2默认保留已认可的`blue_gray`正文：navy `#24445C`、slate `#7892A5`、gold `#AE9B74`、pale `#EDF2F5`，图表标题使用`#4C687B`。正文一级章节为紧凑深蓝白字带，图表编号与标题共用蓝灰白字带、默认17pt行距，列头为`#E8EFF4`浅底与`#24445C`深字。用户选择其他方案时，按[style-presets.md](style-presets.md)使用`forest_sage`、`burgundy_slate`、`ink_gold`或`graphite_teal`整套设计，文档与图表配色同步；不随机轮换或改动已认可正文。

章节可按方案使用实心带、浅底或细线；附录默认改为浅底深字与细线，图表标题浅带深字、白底深字列头。通栏及双图标题区域始终保持所属栏宽，双图中间0.65cm真实空白。长标题正常换行，不增加无内容空高、不裁切；数据行白底或轻斑马纹，关键行轻填充，避免连续深色条。主题与附录模式均支持少填充偏好，用户模板优先；字体和研究要求不随方案变化。

默认中文为楷体（KaiTi），英文和数字为Times New Roman，覆盖标题、正文、表格、图表、目录与页眉页脚；用户可另行指定模板字体。默认中文正文10.5pt、15.5pt行距，层级由字号和字重建立，不用不同中文字体区分角色。Word的East Asia字体与ASCII/HAnsi字体分别设置，清除会覆盖指定字体的主题继承；图中的中英文混排、刻度及图例也显式应用相应字体。真实安装字体、Word实际字形与PDF导出字形须一致检查；只设置名称不足以证明已正确显示。固定行距下仍须确认字形、上标与强调数字无裁切。

色块必须与语义对应。章节、图表标题和列头分别采用一致的内边距规则，按所选主题及正文/附录区域区分层级；财务小计采用轻填充。关键财务行按标签选择；`subtotal_rows`为数据行零基索引，错一行会突出非经营项等无关字段。双图各有独立标题区域与一行简短资料来源，中间留白贯穿标题和图组，不给整个图组套厚边框。仅调整版式时保持既有研究文字和数值不变。图表下方不附解释注、免责或口径长文；单位、期间、分母、A/E移入标签、标题或表头，重要假设在正文或方法表只交代一次。来源ID、页码、工作表/单元格及完整URL只存support。

## 工程实现

默认排版模块为 `scripts/research_editorial_layout.py`，公开类为 `EditorialReport`（`ResearchEditorialLayout`的别名）。它依赖Python、python-docx和Pillow，负责可编辑DOCX装配，不提供事实抓取、估值计算或PDF导出。用`Theme.preset(name, **overrides)`选择方案，完整选择规则见[style-presets.md](style-presets.md)。执行前检查当前主题与接口是否实际落实字体、颜色、正文/附录层级和纯来源行；规范同时约束独立生成的图表，不能仅调整DOCX样式。研究判断、数据正确性和最终视觉验收仍由生成流程完成。

通用制图模块为 `scripts/chart_style.py`，依赖Matplotlib，不包含公司数据、固定输出目录或图号筛选。`configure(theme="blue_gray")`接收与Word相同的方案名称字符串，不接收Theme对象或字典；图表没有独立的附录区域参数，同一业务的系列色在正文与附录中保持一致。函数默认查找系统已安装的KaiTi与Times New Roman，也可传入`kaiti_path`、`times_path`和可选的`times_variant_paths`（粗体/斜体文件）。脚本核对实际字体家族，缺少字体或路径指向其他字体时直接报错，不静默回退。字体文件由使用者所在环境提供，不随公开skill打包。

将scripts目录加入Python搜索路径后，以下合成数据仅用于演示接口：

```python
import chart_style as charts

style_name = "blue_gray"  # 与Word的Theme.preset使用同一名称
charts.configure(theme=style_name)  # 或加传本机字体路径
fig, ax = charts.figure(wide=False, height_cm=5.4, font_size_pt=8.75)
ax.bar(["2024A", "2025A", "2026E"], [100, 120, 135],
       color=charts.PALETTE[0], label="收入示例")
charts.style(ax, "亿元")
charts.legend(ax, ncol=1)
audit = charts.save(fig, "outputs/figures/example_revenue",
                    final_width_cm=8.085, font_size_pt=8.75, compact=True)
```

`figure()`支持`width_cm`、`height_cm`和`font_size_pt`，默认半栏宽8.085cm，`wide=True`时通栏宽17.06cm。`save()`接收不含扩展名的输出路径，默认导出320DPI PNG、轮廓化SVG与`.audit.json`；`final_width_cm`指定最终插入宽度，`font_size_pt`默认8.75，`compact=True`按源Figure的矢量内容边界迭代重绘，保留物理字号并压缩外缘空白，默认`pad_cm=.08`，不裁切既有位图。封面小图显式使用8.5pt。Word必须按相同目标宽度插入，不能再次缩小。

导出前统一中英字体并检查边界外文字，导出后核对SVG字形字体及缺字警告。默认`strict=True`，字体或越界检查失败时保留预览与失败记录并抛错；不能将脚本结束或生成图片当作通过。审计记录包含实际输出物理尺寸、目标宽度、目标与观测字号、内容边距及PNG/SVG哈希，不预设“数据未改变”。这些检查不能替代数据核对、标签重叠、图内有效空间与最终页面目检；最终PDF中的实际插入尺寸仍须另行核对。

Windows且已安装桌面Microsoft Word时，可使用通用 `scripts/export_word.ps1`：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/export_word.ps1 -DocxPath "outputs/report.docx" -PdfPath "outputs/report.pdf"
```

上述执行策略参数仅作用于本次PowerShell子进程，不更改系统配置。导出器预检KaiTi和Times New Roman，确认新建了独立Word进程后隐藏运行；更新本地目录、页码及引用字段，在各正文/页眉页脚文本区域应用指定字体，重新分页，保存传入DOCX并导出PDF。它不刷新外部链接或数据库字段，不改Word全局设置，仅关闭自己打开的文档与创建的实例；若新实例无法确认独立，停止操作而不退出已有Word。传入本次生成稿，不能把原始资料当作输出稿。返回页数和文件哈希仅证明导出完成，仍需渲染PDF、检查实际字体、目录页码与全稿版面。

将skill的scripts目录加入当前Python搜索路径后，可使用以下接口；示例中的内容须由本次研究填充，不是默认研究结论：

```python
from research_editorial_layout import EditorialReport, Theme

r = EditorialReport(company="公司名", ticker="证券代码", date="研究截止日",
                    theme=Theme.preset("blue_gray"))
r.cover(
    params={"title": "具体研究命题", "facts": [("行业", "已核验行业")],
            "valuation": "估值结论、方法与适用条件", "risks": "关键风险"},
    theses=[{"lead": "核心判断。", "text": "事实、机制与投资含义。"}],
    forecast={"headers": ["指标", "年度A", "年度E"],
              "rows": [["预测指标", "实际值", "预测值"]],
              "title": "主要预测", "source": "资料来源：估值模型、团队分析"},
)
r.toc()  # 原生TOC域；须在文档引擎中更新
r.heading("行业格局", level=1, number=1, page_break=True)  # 首章段前分页
r.subheading("支持投资逻辑的行业变化")
r.paragraph("证据及其经济含义；重要假设在此或集中方法表交代。", bold_lead="明确判断。")
r.table(["指标", "期间A", "期间E"], [["指标名", "实际值", "预测值"]],
        title="分析表（单位、期间）", source="资料来源：公司公告、团队分析", widths=[6.3, 5.5, 5.5])
r.figure("全宽图.png", caption="原创分析的结论式标题", source="资料来源：团队分析")
r.pair(["左图.png", "右图.png"], ["左图标题", "右图标题"],
       ["资料来源：公司公告", "资料来源：估值模型、团队分析"])
r.begin_appendix("附录一 经营与财务预测", number=7)
# 依次装配重要模型明细和研究补充表图；不因样式简化删字段。
r.end_appendix()  # 后续若仍有正文式内容，应显式退出
r.save("报告.docx")
```

示例来源须按实际数据替换；原创分析的来源写法不适用于外部事实图。`source`传入整理好的简短真实来源；渲染器完整保留该文本，不靠截断来源字符串清除说明。单位、A/E和重要假设在相应标签、标题、正文或方法表中组织，不拼接到`source`。`table`的`title`/`caption`、`widths`/`widths_cm`分别为别名，每组只传一个。`figure`/`pair`使用可读的本地PNG等栅格文件；SVG另存为制图档案，不能假定该模块直接嵌入SVG。`save`只写DOCX；字段刷新、PDF导出和页面渲染另用实际可用的文档工具完成。

`pair`将标题、图像和来源分别放在共享的三行区域中，左右两图间为独立0.65cm空白列。长短标题共用标题行高度，图像从同一水平位置开始，来源也在统一行区域内；这减少由单侧换行造成的错位。标题长度、图像比例与分页仍须在实际导出的页面上检查，结构对齐不等于最终观感已通过。

`figure`/`pair`的`max_height_cm`默认是`None`，图片按所属可用宽度减去左右合计0.24cm插入，不再因固定高度上限缩小整图。仍可显式传入高度限制；若该限制小于按目标宽度保持比例所需的高度，接口报错，要求重绘更扁的图、放宽高度或调整布局。不要以降低字号或压缩图像规避错误。每次使用前核对当前接口，既有文件或旧脚本的参数不能视为最终行为证明。

`begin_appendix(title, number=None, page_break=True)`显式进入附录模式并添加一级标题；`page_break=False`允许后续分组自然连排。以“附录”或“Appendix”开头的一级标题也会自动开启，但普通标题不会自动退出，须调用`end_appendix()`。`content_theme`返回当前区域主题，由`Theme.appendix()`从原主题派生；这只影响随后装配的内容，不重设已完成正文。默认附录图表标题8.8pt/15.5pt行距，附录段后4pt，保持表内数字与图字的可读尺寸。

若用户偏好少填充，传入`Theme.preset(style_name, color_blocks=False)`。正文和附录均不填底色，附录仍保留深字、细线与紧凑间距；不改变研究内容、数据或字体组合。主题和区域模式提供默认支持，用户指定模板优先。

渲染器自动添加图、表编号，传入的`caption`/`title`只写标题内容，不再手写“图N”“表N”；引用采用最终自动编号。目录后若需起正文页，使用首章`heading(..., page_break=True)`（即段落`page_break_before`），避免另加一个分页段把目录尾部挤出空白页。正文各章仍默认自然连排。

目录样式使用Word内置的`toc 1`、`toc 2`，不存在时以`builtin=True`创建；不要另建大小写不同的自定义`TOC 1`/`TOC 2`代替。Word更新目录可能将冲突样式改名为`TOC11`等，造成一级与二级字体/颜色层级丢失。新版`toc()`已配置内置样式，报告装配脚本不再重复创建自定义目录样式；导出后仍检查实际目录层级与页码。

检查PDF实际字体，不能只检查DOCX的默认字体声明。Word更新目录后可能生成采用主题字体的空格或字段字符；若发生回退，在字段更新后分别设置各StoryRange的NameFarEast为楷体、NameAscii/NameOther/NameBi为Times New Roman，再重新分页、保存并导出。只调整字体名称，保留字号、字重、颜色与上标等格式。估值公式中的幂次用原生上标，不以文字插入符号代替。

生成器按本公司经过核实的内容与图表清单装配，不加载上一份样稿的公司数据、证券代码或模型坐标。保持正文与Word表格可编辑，图表数据和来源另存。核实实际提供了哪些功能后，再决定字段更新与PDF导出路径。

正文与多数附录连续流式排版；首页之后、财务附录起始或确有内容需要才插入硬分页。章节标题不等于新页。最终目录及交叉页码由实际导出的PDF或正确更新的Word字段回填，再次导出复查，不能套用设计阶段页码。跨页位置不稳定时优先使用图表号或附录编号。

Word图片段落用自动/单倍行距，不能继承正文的固定行距，否则图片可能被裁至一行。新版`figure`/`pair`已处理；若在首页窄栏直接调用`add_picture`，必须为图片所在段落单独设置`paragraph_format.line_spacing = 1`。图注与图片保持同页，图片与资料来源同页。短表尽量整表同页；长表保证标题和前三行相连，续页重复表头。页眉页脚的Tab需清除继承的居中制表位，实际核对公司名与页码是否右对齐。

以最终插入尺寸制图：默认完整画布通栏17.06cm、半栏8.085cm，正文图的图例、轴标题/刻度、单位和数据标签统一8.75pt，封面小图8.5pt，建议区间8.5–9pt。减少画布外缘、图例周围与坐标区上方的无效空白，使数据区在色带内充分展开；保留单位、期间、A/E和必要说明，不裁切既有位图。不要把更宽源图缩入半栏后仍按源字号宣称可读。半栏内再次切两个窄面板时应改通栏。不同单位/季度用独立面板并明确标注，不能共享轴造成同口径错觉。清除无意义底色，用A/E、虚线与轻分界表达预测期；柱图系列色跨期保持一致。300DPI以上PNG与SVG同时保存，高度与分页以最终可读性决定，不固定页数。

## 视觉验收必须独立于内容验收

正文所有文字、表格文字、来源和完整图画布（含坐标、图例、数据标签）必须位于所属标题/章节色带的左右边界内。正文默认左右各内缩1.2mm，标题带铺满所属版心；清除段落和表格继承的外凸，禁用行末标点悬挂（`overflowPunct=0`），保留正常中文禁则。检查实际字符含行末中文标点，不能只比较段落框。单图与双图均显式居中，清除首行缩进，左右各留1.2mm等量内边距；传入超出版心的图宽时按可用宽度收束，不拉伸图片。以最终PDF的色带、字符和图片外框核对边界及中心线，不能只比较源图像素或名义栏宽；图内标签仍须在制图阶段检查。

先做首页、双图正文、估值和附录的代表页，实际查看后再推广全稿。最终PDF需渲染全部页并逐页以可读尺寸打开；联系表仅用来发现漏页/重复页，不能替代逐页查看。除溢出、断表、乱码外，还须判断：

1. 五秒内能否看清公司、研究命题、核心判断、估值性质。
2. 图例颜色是否与图中序列对应，预测期变色是否有解释。
3. 是否仍存在逐页相同结构、一页一图、图后重复表和大段流程说明。
4. 是否反复出现大段底部空白；若由硬分页或内容碎片化造成，合并相关内容。完整图块移到次页、章节结束等自然分页可保留合理空白，不机械规定填满比例。
